# Polymaker rename migration — 2026-11-25

Starting commit: `7b8faa9a7b1272e5dda8fdb3ac9d2f73fcbad979` (Community `main` after #88). Upstream source: [Donkie/SpoolmanDB#518](https://github.com/Donkie/SpoolmanDB/pull/518), merge commit `e86be9f137e6614f3013df32e3ec4df1e79de258`.

This is an **intentional breaking catalog migration**. It applies the upstream Polymaker name cleanup: names no longer repeat the material (`PolyLite™ PLA {color_name}` → `PolyLite™ {color_name}`, PLA). Material changes from the same upstream PR are not included (see below).

The new templates are exactly upstream's. All 872 new IDs for records upstream also has are identical to upstream's (checked by compiling `polymaker.json` at the merge commit); the other 174 are Community-only colours in the same groups. Upstream #518 changes no colour names or other fields in this file; its `esun.json` change is a trailing newline only.

Four of the old Community templates (`PolyLite™ ABS`, `PolyLite™ LW-PLA`, `PolyMax™ PETG`, `PolyDissolve™ S1 (PVA)`) have a no-break space (U+00A0) after the ™ where upstream has a plain space. `--upstream` does not match them, so they are passed as explicit `--rename` pairs; the new templates use a plain space, as upstream does.

Reproduce with:

```sh
N=$'\u00a0'
python scripts/rename_migration.py --file polymaker.json \
    --upstream e86be9f137e6614f3013df32e3ec4df1e79de258~1 e86be9f137e6614f3013df32e3ec4df1e79de258 \
    --rename "PolyLite™${N}ABS {color_name}" "PolyLite™ {color_name}" ABS \
    --rename "PolyLite™${N}LW-PLA {color_name}" "PolyLite™ LW {color_name}" PLA \
    --rename "PolyMax™${N}PETG {color_name}" "PolyMax™ {color_name}" PETG \
    --rename "PolyDissolve™${N}S1 (PVA) {color_name}" "PolyDissolve™ S1 {color_name}" PVA \
    --ref https://github.com/Donkie/SpoolmanDB/pull/518 --source e86be9f137e6614f3013df32e3ec4df1e79de258 \
    --base-ref 7b8faa9a7b1272e5dda8fdb3ac9d2f73fcbad979
```

Retired IDs disappear from the published catalog. Existing Spoolman spools keep their local imported data; Spoolman does not read the registry or follow these mappings.
